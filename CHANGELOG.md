# Changelog

## Unreleased

- Stage 0: project skeleton with solution (Core, App, Tests), tray icon with an "Exit" menu (English and German), CI workflow, MIT license.
- Stage 1: search core in `FileDetective.Core` without file system or database: `SearchNormalizer` (search form of names), `SearchQuery` (input parsing: quotes, `\`/`/` splitting, type filters, max. 8 terms, mode), `MemoryIndex` (16-byte entries in 65,536-entry blocks, 16 MiB name segments, `ReaderWriterLockSlim`, parallel matching with inherited folder masks, bounded best lists per thread, deterministic ranking, cancellation), `SearchEngine` with `IEntryResolver` (id to full path) and `IUsageLookup` (entries opened through the tool). Placeholder class removed.
- Measured (stage 1, Release build, AMD Ryzen 7 8745HS, 8 cores / 16 logical processors): search over 1 million generated entries, median per input, 4 threads: 5–14 ms for typical inputs, 14–30 ms for the worst case (single letter `e`, every entry is a hit); all 16 logical processors: 4–11 ms. Target under 50 ms on 4 cores is met. Debug builds are about 2–5x slower.- Stage 2: database and storage in `FileDetective.Core`: `IndexDatabase` (SQLite schema from PLAN.md 6.1, `meta.schema_version`, WAL, `synchronous=NORMAL`; a file with a foreign schema version or a damaged file is renamed to `index.db.bak-<timestamp>` and recreated), `IndexStore` (only entry point for changes: entry numbers never reused and kept over restarts through `meta.max_id`, locations, batches written in one transaction and then applied to the `MemoryIndex`, subtree deletion, rename/move, removing a location, known children of a folder, loading the database into memory in one pass), `DatabaseEntryResolver` (`IEntryResolver`: entry number to full path and display data), `UsageTracker` (table `usage` keyed by path, `IUsageLookup` through a thread-safe map entry number to last opening). `MemoryIndex` got `UpdateMTime`.
- Measured (stage 2, Release build, AMD Ryzen 7 8745HS): loading 1 million entries from the database into the `MemoryIndex` takes 0.55-0.7 s (about 1.4-1.8 million entries per second); target under 3 s is met. Writing the 1 million entries in batches of 50,000 took about 8 s.
