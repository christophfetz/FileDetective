## 0.3.0

- Stage 13: "Open with" and image notes (PLAN.md 11.4), decided with the user after the first test of version 3: photos and crooked scans have no text the recognition can read, so they could not be found.
- "Open with…" in the right-click menu of the search bar (files only, not folders) and in the screenshot history (button and menu). It shows the Windows dialog "How do you want to open this file?" (`SHOpenWithDialog` with `OAIF_ALLOW_REGISTRATION | OAIF_EXEC`), the same as "Choose another app" in Explorer; no list of programs of its own. Before it, the same check as for opening (`ExistenceCheck`, unreachable locations refused); an opening is counted only if an app was chosen.
- Image notes: a "Note" box in the side panel of the screenshot history, above the recognized text. It is saved when the box is left, when another image is chosen and when the window closes; an empty box removes the note. Notes are never written into the image or its name (rule 2) but into the new table `notes(path, text, changed_utc)` in `index.db`, added like `hashes` (`CREATE TABLE IF NOT EXISTS`, schema version stays 1). The key is the full path (without case), so rebuilding and renumbering the directory and switching the text recognition off leave the notes alone.
- `FileDetective.Core`: `ImageNoteService` attaches the stored notes to their entries and follows the directory through `IndexStore.Changed`: after a rebuild the notes come back with their images, a move or rename reported by the directory takes the note along, and a removed image loses its note only if a location still contains the path and the file is gone from the listing of its folder (local only, nothing is opened); a removed location keeps the notes. `ImageTextIndex` keeps the notes apart from the recognized texts (`SetNote`, `GetNote`, `RemoveNote`, `ClearNotes`, `Combine`); `Find` matches every term in the text or in the note, so one word may stand in each, and lists images with only a note too. The hit snippet of mode "Image text" shows the note before the text. `IndexStore`: `ReadImageNotes`, `SaveImageNote`, `DeleteImageNote`, `MoveImageNote`. Notes are cut at 2,000 characters.
- Notes work whether the text recognition is on or off; the search box of the history therefore stays enabled when it is off and finds the notes.
- Tests: 9 new (`ImageNoteTests`: search by note, by text and by both, snippet, notes with the recognition off and without opening a file, surviving restart, switching off and rebuilding, deleted image, image still on disk, removed location, rename, blank text and cutting, history filter) plus the extension check of an existing database. 825 tests in total.

## 0.2.0

Off by default (setting `ocrEnabled`); while it is off no image is read, nothing is queued and the mode is not in the Tab cycle. `FileDetective.Core`: `ImageTextRules` (`.png .jpg .jpeg .bmp .gif .tif .tiff`; skipped are `*.thumb.jpg`, files below 5 KB or above 50 MB and cloud-only files, which are never opened), `ImageTextFolders` (setting `ocrFolders`, preset with the Windows Screenshots folder from `SHGetKnownFolderPath(FOLDERID_Screenshots)` wherever it is redirected (`KnownFolders`); only local folders, UNC paths, network and removable drives are refused; folders that lie in no location become locations of their own), `IImageTextRecognizer` with `WindowsImageTextRecognizer` (`OcrEngine.TryCreateFromUserProfileLanguages`, decoding with `BitmapDecoder` (first frame of a GIF, EXIF orientation), scaled down above `OcrEngine.MaxImageDimension`), `ImageTextService` (queue on one thread with the lowest priority and background I/O through `LowPriorityWork`, cancelled at exit; new and changed images arrive through the new event `IndexStore.Changed` from scans and the watcher; switching on and every start fetch missing and invalid texts from the directory without touching valid ones; an image is opened only through `ILocalFileAccess.OpenRead` after the directory and a fresh listing of its folder say it is local, an image, of the allowed size and not in the cloud; switching off deletes all stored texts at once, removing a folder deletes the texts of its images at once; a settings change while an image is read drops that result), `ImageTextIndex` (text in search form per entry in memory), `ImageTextSearch` (all terms in the text, newest first, at most 100, empty input = newest images, type filters on the file name, only images that still lie in a folder), `ImageTextSnippet` (text place around the first hit with the terms marked, also across umlauts), `SearchMode.ImageText`, `BarState.CycleMode` with the image text switch, `MemoryIndex.IsBelowAny`. With the image text on, its folders are always recorded by the scan even below an excluded path. `FileDetective.App`: one-time hint in the search bar in mode All ("Search the text in screenshots? Switch on", gone for good after switching on or dismissing, setting `ocrHintDismissed`), mode "Image text" with rows of preview (64 px from `IShellItemImageFactory`, loaded on a background thread, only for local files and never for cloud-only files), name, text place and date; Enter opens, Ctrl+Enter shows in Explorer, Ctrl+C copies the image (as picture and as file), Ctrl+Shift+C copies the recognized text, context menu entries for both; settings area "Image text" with the switch (switching off asks first), the folder list (add, browse, remove), the progress ("Image text: 120 of 3,400 recognized") and a hint with a button to the Windows language settings if no recognition language is installed. Texts in both language files. Version 0.2.0.
